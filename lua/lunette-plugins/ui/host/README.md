# UI host

Provides `lunette/ui-host`: panels with root mount points, element kinds and visuals, layout through the native layout tree, pointer and touch routing, focus and traversal, motion, and drawing through the toolkit shader. The [design documents](../../../../docs/development/ui/README.md) describe the architecture this provider implements.

A consumer creates a panel with `newPanel` and binds its `root` mount point, usually through the [React-like library](../react/README.md). Kinds come from `registerKind`, and visuals from `registerVisual`; the [standard kinds](../standard/README.md) are the reference. Element trees are reconciled by slot and kind, composite kinds expand into other elements, and node handles reach visuals, event handlers, and refs. A panel is presented in the world, following the head, as a dialog in front of a parent, or attached above a target surface, and it can be flat or curved. A portal renders its children into an overlay panel raised above its anchor.

An outlet is declared with `uiHost.outlet` and placed with the `lunette/outlet` kind; `contribute` adds an owner-scoped contribution, a mount point adapter that the host binds once for each placement and renders after the panel's root in the same commit. Contributions render in the outlet's order or by contributor name, a contribution whose version the placement cannot accept is skipped and reported against its contributor, and a contribution's errors are reported against it without disturbing the rest of the panel. An attributed outlet wraps each contribution in a frame that names the contributing plugin's definition name and clips it to the placement's `maxHeight`. `inspect` lists each contribution with its owner and the number of placements it renders in, and `inspectNodes` reports nodes inside a contribution under the contributing owner.

`overrideKind` stacks a replacement on a registered kind, and a second `registerVisual` under a name stacks on the visual. Default appearance resolves every kind and visual name to its base registration and the theme to the base theme, so a broken override is undone without restricting what can be overridden. The accessibility settings apply in either appearance. Holding both thumbstick clicks toggles default appearance unless `appearanceChord` is off. `inspect` lists every live override with its owner. An override can arrive before the kind it replaces; one whose layered result is not a valid registration is skipped and reported against the host. Default appearance belongs to the host's activation, so reloading or reconfiguring the host turns it off.

Pointer input arrives through the surfaces contract from the interaction service, so rays drive hover, press, drags, and scrolling, and a scroll carries the pointer's position in the node. Tracked fingertips press nodes by touch, and a fingertip hovering a panel reports its hand as near, so the same hand's idle ray stands down. A press anywhere other than a host panel dismisses every overlay, and a portal that asks for handoff takes over a ray press held on its opener, so a dropdown opens on press and chooses on release over an item. Keys reach the focused node of the panel that holds session focus, and unconsumed keys traverse: Tab and the arrows move focus, Enter and Space activate or engage, and Escape dismisses. A controller's thumbstick and face buttons traverse while no ray points at a host panel.

These parts of the design are not implemented. Pick hooks, grab-sphere interactors, and gesture claims that transfer a capture between nodes are absent; arbitration covers only a fingertip standing a ray down. Changing a kind's current registration remakes its nodes, so host-owned state such as focus, scroll offset, and caret position resets rather than carrying across. Text is drawn glyph by glyph from the native glyph atlas, `lunette.glyphAtlas`, which generates a multi-channel distance field for each shaped glyph id with msdfgen, so drawn glyphs sit exactly where shaping placed them and clip, bend, and fade like boxes. The atlas generates a glyph's field on a worker thread the first time the glyph is drawn, and the glyph appears a few frames later. It keeps every glyph for the Lua state's lifetime without eviction or reference counting, holds a fixed number of pages, and reserves no share for the interface fonts, so once the pages are full a new glyph is reported and draws nothing. Variable faces draw their default instance. A font registration that ends leaves its face in the native fonts, because they have no removal. Commits run once per frame in the scene update phase, so a change made during pointing renders on the next frame.
