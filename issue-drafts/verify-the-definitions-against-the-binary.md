# Check the generated definitions against the running binary

Labels: enhancement

## Current state

`etc/lunette/definitions.luau` declares the runtime that `lunette check` and a user's editor check Lua against. It is generated by `crates/lunette-generate-definitions` from the lovr-docs metadata, and `lua/lunette/init.luau` is a hand-written stub declaring the API the Rust registers. Nothing compares either against what the binary exposes.

The mismatch occurs in both directions, and both have already happened. A declaration for something absent from the runtime passes the check and defers the failure to a session: `io`, `lovr.vector`, and `lovr.quaternion` were each declared and absent, and the `io` declaration masked four crashes in mullion's error paths until someone probed the binary by hand. Something present and undeclared is invisible to the checker and to an editor, which is the larger gap: the runtime's global `vector` carries around thirty members against the eleven lovr-docs documents.

The hand-written stub drifts the same way. Its own header states that it is kept in step with the Rust registration surface by hand. One reading of it against the Rust found `Sink.scrollDiscrete`, `Window.contentType`, `lunette.setSceneEnabled`, `lunette.sceneEnabled`, and `lunette.restart` missing, each of which made a documented call fail the check. Those five are declared now; nothing stops the sixth.

## Change

A test instantiates a Luau state from the binary, with the `lovr` modules and the `lunette` module registered as a session registers them, and compares the live surface against both definitions files in each direction.

Present-but-undeclared is the cheaper half: walk the live tables and look for each key in the definitions. Declared-but-absent needs the definitions parsed, which means enumerating declarations through Luau's AST in `crates/lunette-lovr/src/analyze.cpp`. That half is the one that catches a declaration with nothing behind it, which is the `io` case, so it stays.

A regular expression over the definitions text does not substitute for the AST. The declarations nest, carry intersections that span lines, and are generated, so a pattern over the text would break on a generator change and keep passing on a runtime change, which reverses what the check is for.

lovr-docs' own `api/main.lua` validates its metadata against a live `lovr` table as it aggregates, and `lunette-generate-definitions` runs it. That covers part of the LÖVR half already, under a flag that is off, and is worth reading before writing a second implementation of it.

## Done when

`cargo test --workspace` fails if a name is added to the Rust registration surface and not to `lua/lunette/init.luau`, and fails if a declaration names something the runtime does not carry.
