# Human test plan for lunette v1

The forty acceptance criteria in [the v1 design plan](../design-plans/2026-08-05-lunette-v1.md) are covered by the automated tests plus the Lua specs. This plan is the rest: the steps a person runs against real hardware, a real host desktop, a real XR runtime, and real client toolkits, because the property being checked is not one a test process can observe.

The groups are ordered by what they need. Group A needs nothing but the repository. Group B needs a desktop session. Group C needs a GPU and `monado-service`. Groups D and E need the headset powered on.

## What has been run

Group A, C1, D9, D12, D13, E1, E2, the first half of D1, and the recorded half of D3 have been taken against a Bigscreen Beyond on Monado in service mode. C2 was attempted and is void. The rest of groups B and D are untouched. [The findings](../milestone-0-findings.md#what-the-test-plan-has-returned) carry every outcome and number.

The run corrected three defects. `CREDITS.md` claimed a static link. Every documented `lunctl` example failed against a real session. `lunette.restart()` segfaulted against a live XR session, which is [recorded in the findings](../milestone-0-findings.md#the-restart-that-faulted) and is the defect this plan has repaid its cost with.

## What needs a person and what does not

The headset being off is the only thing separating Groups C, D, and E from the rest, and powering it on is a step rather than an obstacle. Once the runtime is up, four of those gates run without anyone watching, because the outcome is a pass, a failure, or a number:

- C1, the restart under Vulkan validation layers. The verdict is in the validation output and in the `Quiesced` log line.
- C2, the layer budget degrading under the null compositor. The verdict is in the log.
- E1, whether lunette's session creation succeeds alongside a primary application. It either succeeds or it does not.
- The measurement half of D12, the cost of an idle frame, which comes from a GPU profiler rather than from an impression.

Four gates genuinely need eyes, and no amount of instrumentation substitutes:

- D2, the tuning pass. Its deliverable is replacement constants, which come from someone reaching for a panel and finding the reach wrong.
- D3, sharpness. The whole question is whether a layer looks better than a quad, judged by toggling between them.
- E2, the transparency film. A session that composites but is not transparent passes every automated check and is unusable.
- The legibility half of D14, which is whether an error panel can be read.

## Prerequisites

Every `cargo` command runs inside `nix develop`. The flake is the toolchain: a `cargo` from outside it links against a different LÖVR build environment.

From Group B onward, run lunette with `RUST_LOG=lunette=debug,lunette_compositor=debug`. Several gates are decided by a log line rather than by what the session does, and the default filter drops them.

Do not return a truthy value from `lovr.draw`. `boot.lua:216` discards the headset pass when it does, and the session then presents nothing while reporting itself active, visible, and focused. Four configurations written for this plan had the fault, and it reads as a runtime refusing to composite an overlay.

Run a second OpenXR application for anything in group D or E. An overlay session alone presents nothing, so an otherwise correct lunette is a black headset on an idle runtime.

Set `DISPLAY` as well as `WAYLAND_DISPLAY`. `GLFW_BUILD_WAYLAND` is `OFF` in `vendor/lovr/CMakeLists.txt`, so LÖVR's GLFW is X11-only and reaches a Wayland session through XWayland. Without it the shipped configuration cannot open its window, falls into safe mode, and writes an unbounded error stream: see [a failed window fills the disk](../milestone-0-findings.md#a-failed-window-fills-the-disk).

Set `XR_RUNTIME_JSON` to the runtime's manifest for any run that overrides `XDG_CONFIG_HOME`. The OpenXR loader reads `$XDG_CONFIG_HOME/openxr/1/active_runtime.json`, so pointing that variable at a fixture configuration directory moves the runtime out of reach. LÖVR then starts with no headset and reports no driver, no session, and a layer limit of zero. Nothing announces it, and the symptoms read as a runtime that offers nothing rather than as a runtime that was never found. The first attempt at groups A and C was made this way and had to be discarded.

`lunctl` is the instrument. It evaluates a chunk between frames and prints the result, and it is how a running session is inspected without touching the configuration. Its socket is `$XDG_RUNTIME_DIR/lunette/lunette-0.sock`.

**Monado runs in service mode.** Start `monado-service` and let lunette connect to it. Monolithic mode does not support overlay sessions: `multi_compositor_create` never initialises `z_order` from the session create-info, and only the IPC server calls `set_z_order`. Every overlay and layer gate fails misleadingly under monolithic mode, and each failure looks like a defect in lunette.

## Group B — a desktop session, no headset needed

**Precondition for B4 through B7.** A multi-monitor arrangement with at least one fractionally-scaled display and one at a non-zero logical origin, ideally non-rectangular. `xdg-desktop-portal` with ScreenCast v5 or later, and PipeWire. Membership of the `input` group with `uinput` loaded, or a wlroots host so `wl_virtual` is available. Run B4 through B7 twice: once on wlroots, once on GNOME.

| # | Action | Expect | A failure means |
|---|---|---|---|
| B1 | Run the desktop simulator, spawn a terminal, read `w.width`, `w.height`, and the dimensions of `window:getTexture()`. | The three agree. Record which formats and modifiers the hardware advertised, whether `FOREIGN` or `IGNORED` worked for the import acquire, and — on a Mesa system — whether the `UNDEFINED` transition discarded the client's content. Expect a tiled modifier rather than linear; Alacritty picked `AR24` at `0x0300000000606014` on NVIDIA. The NVIDIA answer on the `UNDEFINED` transition is that it did not discard; the Mesa answer is unknown, and is what the `foreign` flag was written for. | AC1.2 fails, and AC2.1 is unreachable. |
| B2 | Re-run the census harness with `LUNETTE_IMPORT_LAYOUT` and `LUNETTE_IMPORT_QUEUE_FAMILY` crossed, now the release barrier is fixed. | A measurement, not a gate. | The two undefined rows in [milestone-0-findings.md](../milestone-0-findings.md) stay annotated invalid. The release passed the same layout as the acquire, recording `VK_IMAGE_LAYOUT_UNDEFINED` as a barrier `newLayout`, which `VUID-VkImageMemoryBarrier2-newLayout-01198` forbids. They cannot be cited until they are re-run. |
| B3 | `weston-simple-shm`, or `weston-flower`, or a client with dmabuf disabled. | A usable texture. Look for a stride-padding artefact down the right edge, and for a channel swap. | AC1.6 fails. The `wl_shm` fallback is what a toolkit without dmabuf lands on. |
| B4 | Delete the stored restore tokens, then mirror all monitors. | Each monitor identifies itself without a prescribed selection order. Record which backend answered and what it put in `mapping_id`. | The first half of AC3.4 fails. GNOME is expected to put nothing in `mapping_id`: mutter emits a UUID only under a `RemoteDesktop` session, which lunette's is not. |
| B5 | Restart lunette. Then physically move a monitor to a different port and restart again. | Identity survives both. Record whether restore actually skipped the prompt. | The second half of AC3.4 fails, which is the half that matters. Restore tokens are single-use, a rejected token produces a dialog rather than an error, and the pinned `wlx-capture` drops `persist_mode` from the response, so every grant records `Unstated`. "No prompt" is a likely outcome, not a guaranteed one. |
| B6 | Confirm the mirrored panel is live, dismiss it, then re-add it. | `pw-top` shows the stream gone, the host's screen-share indicator clears, CPU drops, and re-adding produces no second dialog. | AC3.5 fails. The absent second dialog is the whole point: a re-add that prompts again means the token was not reused. |
| B7 | Point a laser at the centre of a mirrored panel. Repeat on the fractionally-scaled display, on the display at non-zero origin, and near an edge of a non-rectangular arrangement. | The host cursor lands where the laser points, in all four cases. | AC3.2 fails. The scaled and non-zero-origin cases are the two the arithmetic gets wrong if it is wrong at all. This step also settles the GNOME unknown: does mutter map a bare absolute `ABS_X`/`ABS_Y` uinput device across the whole layout, or bind it to one monitor? If it binds to one, AC3.2 is unachievable on GNOME in v1 — `wl_virtual` is absent there too, and the honest answer is libei, which v1 does not implement. Record that as a limitation rather than chasing it. Also worth noting whether `UNITS_PER_DETENT = 10.0` in `hid/wl_virtual.rs` produces sane scrolling; the value is carried from WayVR, whose own comment on it is "no clue". |
| B8 | Focus a host text editor outside lunette. Point at that monitor's panel and type. Then change the host's focused window without touching lunette, and type again. | Both times, the keystrokes reach whatever the host currently focuses. | AC3.3 fails. `uinput` has never issued `UI_DEV_CREATE` to a kernel from this tree; this is its first contact with one. |
| B9 | Copy on the host and paste into a lunette terminal. Reverse it. Then both directions again for the primary selection. | All four directions carry the text. Record which path each host takes. | AC4.5 fails. GNOME is expected to log `NoDataControl` and bridge nothing, since mutter has no data-control implementation; KDE is expected to bridge, since KWin has carried `zwlr_data_control_v1` for several releases. Both expectations come from reading source, not from a running desktop. Watch for the strict MIME rule: asking for `text/plain` when the host offers only `text/plain;charset=utf-8` yields an empty paste. That is deliberate, and it is the rule most likely to look like a bug. |
| B10 | Open an application with a dropdown that overhangs its toplevel, and click an item in the overhang. | The click reaches the popup's surface in surface-local coordinates. | AC4.4 fails. This is the most partially-discharged gate in the plan: the whole path is already driven through a real `wayland-client`, so this is confirmation against a real toolkit rather than discovery. |
| B11 | Run `wayland-info` inside a spawned client's environment. | Exactly one `wl_output`, and no others. The toolkit lays out normally against a single monitor. | The first half of AC2.5 fails. A client shown more than one output lays itself out against a monitor arrangement lunette did not intend it to see. |
| B12 | Arrange panels across two tags in the simulator, quit, and restart. Then unplug a mirrored monitor and repeat. | The arrangement comes back both times. | AC5.3 fails. This step also shows whether the shipped configuration writes at the right moments: it saves on drop and on quit, so a session killed rather than quit keeps only what a drop wrote. |

## Group C — a GPU-headless session

A GPU and `monado-service`. No display and no headset needed.

| # | Action | Expect | A failure means |
|---|---|---|---|
| C1 | With two clients connected, run `lunctl 'lunette.restart()'` with Vulkan validation layers installed. | Per abandoned image, exactly one `VK_OBJECT_TYPE_IMAGE` and one `VK_OBJECT_TYPE_DEVICE_MEMORY` "Object has not been destroyed", under `VUID-vkDestroyDevice-device-05137` and its `OBJTRACK` companion. Nothing else. Record four numbers, three of them read off the `Quiesced { took, discarded }` log line: whether the quiesce covered every GPU object, whether re-import succeeded for every retained dmabuf, whether any client noticed, and the end-to-end duration. | AC5.5 fails. Installing the layers first is what makes this worth doing at all — a driver tolerating a missed object would look like a pass. The two expected leaks are recorded in [decisions.md](../decisions.md): LÖVR's morgue is emptied only by `gpu_destroy`, so imported images are forgotten rather than destroyed, and there is no reachable way to flush it. Any other validation output is a real miss, and the criterion fails even if the session recovers. |
| C2 | Under the null compositor (`XRT_COMPOSITOR_NULL=1`), claim layers. | `getLayerLimit` reports 0, the budget is 0 slots, nothing is granted, nothing is attempted, and the refusal is logged once per claim rather than once per frame. | A regression on a fixed defect. Cheap, and worth running before Group D. |

## Group D — Monado in service mode, headset powered on

Run Group B first if you can. A broken import path looks like a rendering bug from in here.

| # | Action | Expect | A failure means |
|---|---|---|---|
| D1 | Start with the shipped default configuration. | A terminal spawns onto a panel at the stated pose and metre size. Check the size against a known reference, such as arm's length. It is legible, the right way up, and does not move with the head. | The first half of AC5.1 fails, and AC2.1 with it. |
| D2 | Grab the panel and move it. | It follows the hand, and the interaction feels right. | This is the one gate that is not yes-or-no. It is the tuning pass. Every constant in `interaction.TUNING`, `laser.STYLE`, and `arc.TUNING` is a first guess: grab dead zone, reach, scroll scale, haptic strength, arc radius, arc step. The deliverable of this gate is replacement numbers, not a tick. Grab-to-resize was deferred until after it. |
| D3 | Open a text-heavy terminal, show it in-scene at reading distance, claim a layer, and toggle back and forth rather than judging either state alone. | The layer is visibly sharper. | AC2.2 fails. This is the single highest-value item in the plan: no session has granted a layer to a real panel at all, which is why so much of the layer chapter is unresolved. Record five things. The `maxLayerCount` Monado reported — expect 128, which is `XRT_MAX_LAYERS`, yielding a 12-slot budget at `LayerBudget::CEILING`. The free-list hit rate in ordinary use. Whether the ladder's rungs are right; the only real size seen so far is one 800x600 terminal, which rounds to 1024x1024. Whether format conversion was needed — expect yes, because a client's `AR24` is `FORMAT_BGRA8` non-sRGB and a layer image is `FORMAT_RGBA8` sRGB, so `lovrTextureCopy` degrades to blit as the normal path. And whether `lovrLayerCreate` ever stalled: it ends in `xrWaitSwapchainImage` with `XR_INFINITE_DURATION` inside a retry loop with no escape, which is why `CREATIONS_PER_FRAME` is 1. |
| D4 | Point two hands at two windows side by side at once, then click with one. | Two cursors, each following its own laser. Moving one does not move the other. Focus follows only the clicking hand. | AC4.1 fails. |
| D5 | Focus a terminal panel and type a phrase in a non-US layout, including at least one character that needs a modifier. | The characters the active xkb layout defines. | AC4.2 fails. This is the first real key from real hardware read out of a real terminal. |
| D6 | With a US layout active, call `sink:typeText` with accented letters or an emoji, then type ordinarily immediately afterwards. | The text arrives, and ordinary typing works straight after. | AC4.3 fails. The restore half is already verified in tests by comparing the client's keymap before and after; what is untested is a real toolkit — GTK, Qt, a terminal — recompiling a synthetic layout twice in quick succession and behaving. |
| D7 | Open a named application matched by an `appId` rule. | It is placed without further scripting. | AC5.2 fails. Note that `rules.place` creates a tag a rule names when nothing declared it, rather than refusing, so a misspelt tag name silently produces a workspace nobody meant. That call was flagged for review rather than settled, and this gate is where the decision is made. |
| D8 | Note two client pids. Move one panel by hand. Edit `main.lua` to change the layout, then press F5 or run `lunctl reload`. | The new layout applies, both pids are alive, no client redrew from scratch, and the hand-placed panel keeps its pose. | AC5.4 fails. `tests/reload.rs` already reloads ten times against the real binary with a live client and asserts nothing accumulates; what has not happened is a person watching the room rearrange around a terminal that never blinked. |
| D9 | Reload ten times in succession. | One laser per hand, no duplicated signal handlers, no growing frame time. | The second half of AC5.4 fails. Cheap while you are in there. |
| D10 | Place a panel behind your head so Lua throttles it toward the floor, and confirm the redraw rate dropped — a clock or a scrolling log makes it visible. Then click it and type into it. | The rate drops, and the client still takes input. | AC7.3 fails. The second half is the whole point: a rate of zero passes the first half and fails this one, which is why the floor is approximately 1 Hz. A client that ignores input while throttled fails the criterion even though the rate dropped correctly. Record whether any client set `wp_content_type_v1` at all, which decides how much of the video exemption rests on the commit-rate heuristic. |
| D11 | Walk toward a panel until the scale ladder crosses a step. | The client re-renders, content becomes sharper rather than merely larger, and the layer samples the new buffer instead of scaling the old one. | The second half of AC2.5 fails. Bring one client that honours `wp_fractional_scale_v1` and, ideally, one that does not, so both paths are seen. Record which honoured it, which ignored it, and whether the rungs are the right distance apart or too far to be worth the re-render. |
| D12 | Write a configuration whose scene is genuinely empty — the shipped one draws chrome around every panel and a laser for every hand, so it never is. Reach the steady state with every panel on a layer and nothing in-scene. Attach a GPU profiler, or read LÖVR's own timing. | A measured cost for an idle frame with scene rendering skipped, against the same frame with it drawn. | AC7.4 fails. Do not infer this from frame rate. The flag and the skip are separable, and only the skip saves anything: `setLayers{ main = false }` alone saves almost nothing, and the saving is in not calling `lovrHeadsetGetTexture` and `GetPass`, which is what lunette actually gates. |
| D13 | Attach a debugger to a client, or `SIGSTOP` it. Record frame time before and after. | Frame time unchanged. The panel holds its last content. Other panels stay responsive. | AC7.1 fails. The protocol is unit-tested; the frame-time property is the thing only a real stalled client shows. |
| D14 | Edit a callback in `main.lua` to raise every frame, reload, and watch for several seconds. | An error panel with a message and a traceback. The session keeps rendering. The repeated identical error is rate-limited, with a count, rather than one panel per frame. | AC8.3 fails. Both halves are established headlessly, with two hundred frames through the real dispatcher and one report, so what is judged here is legibility: is the panel readable, does it sit somewhere sensible, does the truncation cut somewhere useful? |
| D15 | Introduce a syntax error into `main.lua` and start with the headset on. Fix it and press the reload key. Then repeat with `LUNETTE_STDLIB_PATH` pointed at an empty directory. | Safe mode with a laser, a panel showing the load error, and a working reload key — not a black headset. Then the ordinary session starts. Safe mode still works with no standard library. | AC8.4 fails. Safe mode must not `require 'mullion'`, which is why the empty-directory case is part of the same step. |

Two things to watch throughout Group D. Both are consequences of API gaps rather than defects, and neither fails a criterion.

A mirrored monitor panel is drawn as an in-scene quad however sharp a layer would have been, because `lunette.claimLayer` takes a window and nothing else.

A hand-placed monitor panel's pose is remembered across a restart but not across a soft reload. There is no per-monitor property store, so it can only live in `mullion.persist`, which is a disk mechanism.

## Group E — Monado, the headset, and a second OpenXR application

Run these before Group D if you can. Phase 3 onward is detailed against the assumption that the overlay session behaves as designed, so a failure here invalidates the premise of D3 rather than merely postponing it.

| # | Action | Expect | A failure means |
|---|---|---|---|
| E1 | Start `monado-service`. Start another OpenXR application and let it take the primary session. Start lunette. | lunette creates its session and runs alongside, rather than failing session creation or displacing the other application. The second application keeps running while lunette starts and while it stops. | AC6.1 fails, and with it the premise the rest of the plan rests on. |
| E2 | Look at where lunette draws a panel, then at where Lua drew nothing. | The panel is over the other application's view. Everywhere else the other application is fully visible, with no grey, black, or tinted overlay film. | AC6.2 fails. The film is the failure mode to look for: a session that composites but is not transparent looks fine in isolation and is unusable in practice. |
