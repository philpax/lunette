# Runtime themes and shared widget appearance

## Goal

Make lunette-owned UI consistently themeable through one owner-scoped public theme service. Ship an enabled-by-default runtime theme plugin with Dark, Light, and Arcade presets, and support rounded scene-rendered windows whose flat titlebar and content form one joined unit.

## Implementation Summary

Add `lunette/theme@1` in `lua/lunette-contracts/theme.luau` and a stable broker provider under `lua/lunette-plugins/theme/`. A normal shipped consumer, `lua/lunette-plugins/desktop/theme/`, selects Dark, Light, or Arcade through that service and supplies controller-accessible preset choices plus the Dark mode shortcut. Arcade is a deliberately saturated full-scope preset with a bundled alternate font, different text/spacing/border metrics, and varied corner radii, including nonzero monitor content. Dark remains the default; Dark/Light retain identical geometry. The broker remains present when the selector is disabled. Use the existing Plugins manager for configuring, disabling, re-enabling, removing, and restoring the selector; no separate configuration is required.

The theme covers UI panel backings, buttons, text fields, choices, lists, region defaults, titlebars and actions, window chrome and silhouette, keyboard backing/keys/legends, manager graph/sidebar/status drawing, error presentation, hints, and pointer-feedback colours. It covers semantic colours, interaction-state styling, font selection and text sizes, control padding/spacing/borders, and corner radii. It does not recolour captured application pixels or change applications' internal widgets. It does not change pointer filtering/trigger-lock behavior, haptics, keyboard layouts/key units, panel placement, manager structural layout, error line limits, or input routing policy.

Preserve explicit provider and object overrides. Convert default-filled appearance configuration to sparse override layers; otherwise current defaults mask the selected theme. Retained panels, controls, keyboards, and titlebars re-resolve defaults without replacing their identities. Distinguish palette-only changes from geometry changes so light/dark switching does not cancel held input or lose focus/drafts.

Use specific rounded-rectangle geometry helpers beside the theme provider, not a general layout/container framework. Scene content uses clipped meshes with existing colour-conversion shaders. UI default faces use rounded polygons clipped to declared rectangular clips; text and custom hooks receive conservative rectangular content clips inside the outer silhouette. Hooks remain responsible for obeying their supplied clip; arbitrary shader/stack misuse is not forcibly intercepted.

For flat headed scene surfaces, round only the titlebar's top outer corners and content's bottom outer corners. Adjoining edges stay square, the titlebar-to-content margin is zero, and the outer border has no doubled seam. Unheaded surfaces use all four corners. Monitor content radius is separately configurable. Base, Dark, and Light use zero; Arcade explicitly uses 0.012 m to exercise monitor content clipping. The operator selected a scene-only implementation: granted OpenXR layer content stays square, with no automatic rendering-mode fallback. Curved scene content supports rounded corners, but a flat titlebar cannot join a curved body; retain separate titlebar placement there and document the exception.

Use theme consistently in public identifiers, plugin ids, filenames, documentation, and manual check names. The neutral global `theme.Theme` and component-specific `ui.Theme` have different responsibilities; qualify imports/types where both appear. The operator explicitly requested existing filename renames too. Rename `lua/lunette-plugins/ui/tests/skinning.luau` to `lua/lunette-plugins/ui/tests/theming.luau`, preserve its existing cases, and update their wording/direct references. This is a test-file move, not a new regression file or case. No other skin-named file was found in lua/dev/examples/docs/crates/etc; generated LÖVR skeletal skin API names are unrelated and remain unchanged.

No new regression-test files or cases are authorized. Adapt existing relevant cases/fixtures without changing their purposes, run standing checks, and require named manual session/headset checks. The operator accepted no automated GPU appearance validation and, after review, no automated broker arbitration/reentrant lifecycle coverage. The checked public registration example provides the accepted manual logic workflow. The operator now requires incremental commits and selected final-combined-state-only full CI: intermediate commits may be incomplete, with that status disclosed. Follow the commit batches and consent gates below. No agent XR launch or push is authorized.

## Implementation Plan

### Phase 1: Neutral theme vocabulary and owner-scoped selection

1. Add `lua/lunette-contracts/theme.luau` without importing UI, keyboard, panels, or desktop implementations. Define deeply immutable complete `Theme` values with the exact fields below. `ThemeOverrides` has the same groups/fields, each optional; a supplied font is a complete union value, not a partial font. Reject unknown fields, non-plain tables, nonfinite numbers, and invalid domains. Freeze detached nested tables and RGBA arrays.

   | Group | Exact fields | Units and validation |
   | --- | --- | --- |
   | `colors` | `background`, `elevatedBackground`, `foreground`, `mutedForeground`, `control`, `hovered`, `pressed`, `disabled`, `border`, `focus`, `selection`, `error`, `errorBackground`, `success`, `warning`, `ownershipEdge`, `dependencyEdge`, `pointer`, `pointerHovered` | RGBA arrays of exactly four finite components in [0,1]. |
   | `typography` | `font` | `FontSpec` below. |
   | `typography` | `bodySize`, `smallSize` | Logical UI/manager units, finite and strictly positive. |
   | `typography` | `titleHeight`, `keyboardLegendHeight`, `errorTextHeight`, `hintTextHeight` | Metres, finite and strictly positive. |
   | `metrics` | `padding`, `spacing`, `borderWidth` | Logical UI units, finite and nonnegative. |
   | `metrics` | `rowHeight` | Logical UI units, finite and strictly positive. |
   | `metrics` | `titlebarHeight` | Metres, finite and strictly positive. |
   | `metrics` | `titlebarBorderThickness`, `keyboardGap` | Metres, finite and nonnegative. |
   | `radii` | `uiPanel`, `keyboardBacking`, `keyboardKey`, `titlebar`, `window`, `monitor` | Metres, finite and nonnegative. |
   | `radii` | `uiControl` | Logical UI units, finite and nonnegative. |

   Manager lifecycle states map explicitly to semantic colours; do not leave literals scattered in renderers. `FontSpec = { read kind: 'default' } | { read kind: 'file', read file: string, read size: number, read spread: number }`. File paths are nonempty LÖVR VFS paths; size/spread are finite and strictly positive. The default arm has no size/spread overrides and borrows `lovr.graphics.getDefaultFont()`. Never put a native Font in a theme data snapshot or module-global palette. Light/dark use the default face initially. Keyboard keyUnit, manager structural dimensions, haptics, depth offsets, and placement are not theme fields. Zero radius means square; clamp against actual extents at geometry use.
2. Implement these exact public signatures with contract receiver types and readonly fields:

   ```luau
   export type Snapshot = { read revision: number, read theme: Theme }
   export type Registration = {
     read update: (Registration, ThemeOverrides) -> (),
     read dispose: (Registration) -> (),
   }
   export type FontLease = {
     read font: Font,
     read spec: FontSpec,
     read withFont: (FontLease, (Font) -> ()) -> (),
     read dispose: (FontLease) -> (),
   }
   export type Service = {
     read current: (Service) -> Snapshot,
     read getFont: (Service) -> Font,
     read acquireFont: (Service, Owner, FontSpec?) -> FontLease,
     read select: (Service, Owner, ThemeOverrides) -> Registration,
     read onChanged: (Service, Owner, (Snapshot) -> ()) -> plugin.Effect,
     read inspect: (Service) -> inspection.Snapshot,
   }
   ```

   Revision starts at zero and increases only on effective appearance changes. Registrations, leases, and subscriptions are owner effects. Disposal is idempotent. Updating a disposed registration raises a contextual error without mutation; provider shutdown invalidates registrations. Snapshot/inspection contain no native handles. `getFont()` is an immediate borrowed read: callers must not release it or retain it across a callback/revision. Retained consumers use `acquireFont`. Nil spec acquires the current effective face; a spec acquires that exact validated face. Acquisition invokes no user callbacks or notifications. `FontLease:withFont(run)` rejects a disposed lease at entry, adds an invocation hold before calling run with its exact face, releases the hold on normal/error unwind, then propagates the original error to the existing owner callback boundary. A synchronous theme change or owner/provider shutdown inside run cannot invalidate the face before run returns. It does not swallow errors or acquire a new face. Nested calls hold independently. Direct `lease.font` access is valid only while the lease remains live; callback-spanning use goes through withFont.
3. Resolve each registration's overrides over the complete base theme. Latest registered live selection wins; updating changes its value without moving it ahead of a later selection. Disposal reveals the preceding live selection or base. Do not merge competing palettes field-by-field. Prepare even an inactive registration's font before accepting an update, so restoration cannot fail later. Notify only on effective appearance changes. Detached snapshots/colour arrays must not alias caller input. Update replaces the override layer rather than patch-merging it; omitted fields revert to base for that registration.
4. Validate/acquire before publishing. Invalid public select/update values or font acquisition errors preserve the prior live registration and effective state. Cache file fonts by complete FontSpec within the provider activation. Count selection, lease, and invocation holds; retire a file font only after its last hold ends and the outer notification drain completes. Disposing a selection during notification schedules reclamation, never releases a leased face. Consumers acquire the new lease, recompute/publish retained style/measurement state, then dispose the old lease. Failed refreshes keep the old state and lease until a successful refresh or owner cleanup. Built-in consumers compare applied revision with current revision before later drawing, measuring, describing, or input, so a failed callback cannot strand stale geometry. Resolve from fresh current data and acquire that snapshot's font spec; acquisition contains no callback boundary. Never pair an old callback snapshot with a newer borrowed font. Explicit widget font overrides use specifications and owner leases. Pass retention protects submitted commands, not later Lua use. Never release the borrowed default font. Unwind partial acquisition on failure. Shutdown invalidates effects and clears public cache access after dependent owner cleanup; records with active withFont calls remain retained only by those stacks until final unwind and idempotent release. No module-global teardown registry is allowed. Font assets must be shipped/mounted by their plugin/configuration; require aliases do not resolve font files.
5. Inspect live selections, subscriptions, and font leases using existing registration metadata without native handles. Include outstanding invocation counts as data-only details associated with a font specification for manual unwind observations. Use `lua/lunette-plugins/listeners.luau` and protected error reporting. Commit state before notifications. Each drain iteration captures an immutable Snapshot and listener-registration snapshot; deliver it once to each still-live listener. Skip disposed listeners; newly added listeners wait for the next iteration/change; independent listeners continue after errors. Reentrant selection/disposal commits immediately and marks a pending drain rather than recursing. Finish current delivery, then drain the latest pending effective revision, coalescing intermediate changes. Callback Snapshot is an event value, not a guarantee that current still equals it. Built-in consumers refresh from current, not stale payloads. Reclaim pending unheld fonts only after outermost drain; clear disposed callback references. Do not notify on subscription creation.
